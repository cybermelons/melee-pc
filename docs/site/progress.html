Today the same controls are one flat column with no grouping and no first step. 6Shared lobby URL with port claimingThe room code is the lobby, top right, and clicking it copies the link. Two players pair for real, and a phone-shaped browser is one of them: measured over the routable tailnet address, both claim a port and the touch overlay draws. Two defects had to go first, and both hid behind loopback. signal.mjs sent claims as an object while lobby.mjs calls .indexOf on it, so every state event threw and no claim ever rendered (9fee67ca). Then crypto.randomUUID, which exists only in a secure context: http://127.0.0.1 is one by exemption and a tailnet IP is not, so the page could mint neither a room nor an identity on the only origin a visitor uses (f303d4a8). A third defect was in the offer itself: gathered() cut ICE gathering off after 3 seconds without checking that a srflx candidate had arrived, so on a slow network the offer went out with LAN addresses only. Measured here the first srflx lands at 11 ms while gathering is still open after 12 s, so the cutoff is now a ceiling and the srflx arrival releases the offer (c51bf783). Also measured over an https origin, which is what a shared link really has and which plain http on an IP is not: both ports claim and the data channel opens there too. On the two-seat path this is done: two players pair over a real shared link and both claim a port. Ports 3 and 4 are no longer counted here -- they are not a transport gap but an engine one (#40, out of goal), and the lobby now says so on the tile instead of promising a fix: an unreachable tile reads "2P only" (lobby.mjs:347) and the spec's P3/P4 are drawn unavailable to match. The link is a private tailnet address, shared privately rather than published, so the server needs no auth gate of its own.
